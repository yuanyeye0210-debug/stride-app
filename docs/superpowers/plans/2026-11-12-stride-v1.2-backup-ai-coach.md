# Stride v1.2：数据备份导出恢复 + AI 教练收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给步迹加本地数据备份（JSON 导出/导入、损坏文件隔离、启动完整性检查），并收口 AI 教练（图片压缩与上限、超时重试、友好错误、设置页隐私说明）。

**Architecture:** 不动数据模型与钥匙串。备份以带 `schemaVersion` 的信封包着现有 `AppState`（ISO8601 编解码，与现有 `AppStore.encoder()/decoder()` 同一套）；损坏文件改名隔离、永不删除；AI 侧只加纯函数（重试判定、退避、错误映射、图片上限），网络层循环调用它们，UI 只改文案与备份入口。

**Tech Stack:** Swift 5, SwiftUI, iOS 17+, XCTest, 无第三方依赖。

**Spec:** 本计划即 spec（由 2026-11-12 的 v1.2 优化清单 P0 第 1、3 条收敛而来，范围由 Eric 在主聊确认：“Ok，根据你时间的来吧”；父任务限定只做 A、B 两组）。

## Global Constraints

- Bundle ID 固定为 `com.yg.stride`，不要改。
- 分发走 SideStore + LocalDevPN，版本规则在 `RELEASE-RULE.md`，CI 处理版本号；不要改 `.github/workflows/stride-ios.yml`、`RELEASE-RULE.md`、`apps.json`、`ios/project.yml`，不要推到 main、不要触发发版、不要推分支、不要开 PR、不要合并。
- 不要动钥匙串存储：`AIKeyVault`、`KeychainSecretBox`、`AISecretBox` 不改；`KeychainMigrationTests.swift` 不改。
- 不要做跑步 GPS、饮食扫码、训练模板、Watch、同步、小组件——那些是 v1.3 / v1.4。
- 数据模型不变：`AppState` 不加字段；备份信封是包装层，不是模型迁移。
- 现有行为保留：`AppStore.saveNow()` 继续用 `.atomic` 写 `state.json`；图片压缩沿用现有值（最长边 900px、JPEG 0.62）。
- 本机无 Swift 工具链：`xcodebuild test` 在此 VM 跑不了。每个任务仍按 TDD 写测试（先写测试、再写实现、按任务提交），但红/绿的实际运行验证交给 CI（macOS）或 Eric 在 Mac 上跑；计划执行者必须在报告里如实写“本地未运行”。

## Review Focus

- 损坏的 `state.json` 被覆盖或删除，用户多年的记录无声消失 —— 隔离后原文件必须还在，且 App 必须给出可见提示。
- 导入备份把当前数据整体替换掉，且没有回头路 —— 导入前必须先自动备份当前数据。
- 导入一个来路不明 / 版本不对 / 字段离谱的 JSON 导致崩溃或脏数据 —— 必须先校验再替换，失败时原数据不动。
- AI 请求把原图 / 大图发出去，或在弱网下一直转圈没有提示 —— 图片必须先压缩并设上限，超时必须可重试且报错要说人话。
- 设置页没说清楚数据发到哪里 —— 必须写明发到用户自己填的接口、不经过 Stride/Muse 服务器。
